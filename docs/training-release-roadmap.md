# Training Mini App: Release Roadmap

Дата оценки: 2026-06-06

## Короткий вывод

Текущее состояние: MVP/закрытая бета.

Оценка готовности:
- Закрытый тест с реальными тренерами: 70-75%.
- Публичный релиз для ограниченной аудитории: 50-60%.
- Коммерческий релиз с оплатами и нормальным onboarding: 35-45%.

Реалистичный срок до публичной версии: 3-5 недель.

Реалистичный срок до коммерчески нормальной версии: 6-9 недель.

Оценка дана для одного основного разработчика/агента с регулярной проверкой в Telegram, GitHub Pages и Cloudflare Worker. Если параллельно подключать дизайн/QA/backend-агентов, календарный срок можно сократить, но узкие места останутся: Telegram-проверки, платежи, реальные аккаунты тренера и ученика.

## Что уже готово

- Telegram Mini App открывается по опубликованной ссылке.
- Есть Telegram auth через initData и JWT.
- API защищает пользовательские данные: /training/api/state без JWT возвращает 401.
- Есть роли Ученик и Тренер.
- Есть демо-режим.
- Есть локальный fallback для проверки вне Telegram.
- Ученик видит тренировку дня.
- Ученик отмечает подходы.
- Ученик меняет рабочий вес.
- Ученик сохраняет чек-ин: вес, энергия, забитость, комментарий.
- Тренер добавляет ученика вручную.
- Тренер создаёт шаблон недели.
- Тренер меняет статус тренировки.
- Есть вкладка Штаб: очередь внимания, карточка ученика 360, быстрые действия.
- Есть чат внутри приложения.
- Есть экран баланса и ledger операций.
- Есть webhook /start с кнопкой WebApp.
- Есть защита от повторной обработки update_id.
- Production smoke пройден: страница открывается, админка работает, чат/баланс/подходы/вес работают, console errors нет.

## Главные недостающие блоки

- Реальная привязка ученика к тренеру через invite code/deep link.
- Управление учениками: архив, удаление, редактирование цели, тарифа, цены занятия.
- Редактор тренировочного плана вместо одного шаблона.
- Реальная платёжная логика или ручное подтверждение платежей тренером.
- Push-уведомления через Telegram.
- Нормальная история прогресса.
- Юридические экраны: правила, приватность, поддержка.
- Production-мониторинг ошибок.
- Проверка полного сценария на двух реальных Telegram-аккаунтах.

## Дорожная карта

### Этап 1. Стабилизация текущей беты

Срок: 2-4 дня.

Цель: можно дать 1-2 тренерам потыкать приложение без риска, что базовые кнопки не работают.

Чек-лист:
- [x] Проверить чистоту репозитория и отделить изменения training app от финансового приложения.
- [x] Исправить/зафиксировать кодировку тестов, если PowerShell снова показывает mojibake.
- [x] Добавить короткий экран "Что уже работает / что в демо".
- [x] Добавить явные empty states для тренера без учеников, без планов, без баланса.
- [x] Добавить предупреждение, что пополнение сейчас не является реальной оплатой.
- [x] Проверить mobile viewport 360, 390, 430 px.
- [x] Проверить production smoke после каждого deploy.
- [x] Зафиксировать регрессионные тесты для Штаба, чата, баланса, чек-ина и рабочего веса.

Критерий готовности:
- [x] Новый пользователь понимает, что делать первым.
- [x] Тренер понимает, что это beta/MVP.
- [x] Нет визуально неработающих кнопок.
- [x] Нет console errors на production.

### Этап 2. Invite flow: реальная связка тренер-ученик

Срок: 5-8 дней.

Цель: тренер приглашает конкретного ученика, ученик открывает бота и попадает именно к этому тренеру.

Backend:
- [ ] Добавить таблицу/модель TrainingInvite.
- [ ] Поля: id, coachId, code, status, expiresAt, createdAt, acceptedAt, acceptedByUserId.
- [ ] Endpoint создания приглашения тренером.
- [ ] Endpoint принятия приглашения учеником.
- [ ] Проверка срока действия и статуса invite.
- [ ] Защита от повторного принятия.
- [ ] Автоматическое создание TrainingCoachStudent после принятия invite.

Frontend:
- [ ] Экран/Sheet "Пригласить ученика".
- [ ] Генерация invite-ссылки для Telegram.
- [ ] Кнопка "Скопировать ссылку".
- [ ] Экран ученика "Принять приглашение тренера".
- [ ] Статусы: ссылка истекла, уже принята, тренер не найден, успешно привязано.

Telegram:
- [ ] Поддержать deep link/startapp с invite code.
- [ ] Проверить сценарий на двух Telegram-аккаунтах.

Критерий готовности:
- [ ] Тренер создал ссылку.
- [ ] Ученик открыл ссылку в Telegram.
- [ ] Ученик появился в списке тренера.
- [ ] Чат, планы и баланс относятся к этому ученику.

### Этап 3. Управление учениками

Срок: 3-5 дней.

Цель: тренер может управлять клиентской базой без обращения к разработчику.

Чек-лист:
- [ ] Экран профиля ученика.
- [ ] Редактирование имени/цели.
- [ ] Редактирование тарифа или цены занятия.
- [ ] Архивация ученика.
- [ ] Восстановление из архива.
- [ ] Удаление только для тестовых/ошибочных записей или мягкое удаление.
- [ ] Фильтры: активные, архив, требуют внимания, низкий баланс.
- [ ] Поиск по имени.
- [ ] Подтверждение опасных действий.

Критерий готовности:
- [ ] Тренер может вести минимум 10 учеников без хаоса.
- [ ] Архивный ученик не мешает в очереди внимания.
- [ ] Нельзя случайно потерять историю.

### Этап 4. Редактор тренировочных планов

Срок: 7-12 дней.

Цель: тренер создаёт не только шаблон, а реальный план под ученика.

MVP-редактор:
- [ ] Создание тренировки на дату.
- [ ] Редактирование названия, фокуса, длительности, интенсивности.
- [ ] Добавление упражнения.
- [ ] Редактирование подходов, повторений, веса, отдыха, заметок.
- [ ] Удаление упражнения.
- [ ] Изменение порядка упражнений.
- [ ] Копирование тренировки.
- [ ] Копирование недели.
- [ ] Назначение плана выбранному ученику.

Расширение:
- [ ] Шаблоны тренера.
- [ ] Несколько типов недель.
- [ ] План на 4-8 недель.
- [ ] Быстрое создание "10 тренировок по графику".

Критерий готовности:
- [ ] Тренер может создать индивидуальный недельный план без правки кода.
- [ ] Ученик сразу видит назначенные тренировки.
- [ ] Старые тренировки не ломаются при изменении новых.

### Этап 5. Финансы и платежи

Срок без реального платёжного провайдера: 4-6 дней.

Срок с Telegram Payments/ЮKassa/Stripe: 8-15 дней.

MVP ручных оплат:
- [ ] Разделить операции: pending, confirmed, rejected, charge, bonus.
- [ ] Кнопка тренера "Подтвердить оплату".
- [ ] Кнопка тренера "Отклонить оплату".
- [ ] Комментарий к операции.
- [ ] История баланса по ученику.
- [ ] Цена занятия из профиля ученика.
- [ ] Списание по цене ученика, а не фиксированные 2000.
- [ ] Предупреждение перед списанием.

Реальные платежи:
- [ ] Выбрать провайдера.
- [ ] Добавить env и webhook платежей.
- [ ] Создание payment invoice/session.
- [ ] Проверка подписи webhook платежа.
- [ ] Идемпотентность платежных событий.
- [ ] Автоматическое подтверждение оплаты.
- [ ] Отображение статуса оплаты ученику и тренеру.

Критерий готовности:
- [ ] Ученик не может принять ledger за реальную оплату, если провайдер не подключен.
- [ ] Тренер видит pending платежи.
- [ ] Баланс ученика считается прозрачно.
- [ ] Списание не задваивается.

## Сводная оценка сроков

Минимальная публичная бета:
- Этап 1: 2-4 дня.
- Этап 2: 5-8 дней.
- Этап 3: 3-5 дней.
- Этап 5 MVP ручных оплат: 4-6 дней.
- Этап 10 короткий тест: 3-5 дней.

Итого: 17-28 рабочих дней, примерно 3-5 недель.

Коммерческий релиз:
- Все этапы 1-10.
- С платежным провайдером и уведомлениями.

Итого: 35-55 рабочих дней, примерно 6-9 недель.

- [ ] Редактор планов хотя бы уровня MVP.

## Рекомендованный следующий шаг

Начать с Invite flow.

Причина: без реальной связки тренер-ученик приложение остаётся красивым MVP, но не закрывает главный пользовательский сценарий. После invite flow можно дать приложение 1-2 настоящим тренерам и быстро понять, где продукт проседает: планы, оплаты или коммуникация.
